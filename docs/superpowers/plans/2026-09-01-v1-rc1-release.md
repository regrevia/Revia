# Revia V1 RC1 Public Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish a source-closed, deeply testable `v1.0.0-rc.1` prerelease for genuine macOS arm64 native execution while preserving every existing preview release and explicitly marking the other five targets as pending.

**Architecture:** This public repository owns licensing, onboarding, public evidence verification, deep-trial projects, launchers, release gates, assets, and communication. The private development repository is an external producer: its own development task must return a sealed exact-inventory export containing a licensed Darwin arm64 archive and path-free evidence. This repository never edits, reconstructs, or discloses private implementation source.

**Tech Stack:** POSIX shell, PowerShell, canonical JSON, SHA-256, GitHub Actions, GitHub Releases.

---

### Task 1: Establish the public readiness boundary

- [ ] Add `LICENSE-RC.md` and `docs/rc1-license-and-limitations.md` with the approved non-production developer-evaluation grant: local development, Agent use, public benchmark and research are permitted; production, commercial hosting, redistribution, and reverse engineering are prohibited.
- [ ] Add `docs/cross-platform-evidence.md` with `darwin-arm64=measured-on-native` only after receipt; keep Darwin x64, Linux arm64/x64, and Windows arm64/x64 `pending` until each official native runner produces its own sealed export.
- [ ] Add `scripts/verify-rc1-export.sh` to enforce exact inventory, SHA-256, `1.0.0-rc.1`, target, measured/pending status, license digest, regular-file-only archive contents, forbidden source extensions, credential patterns, governance markers, and private paths.
- [ ] Add `.github/workflows/rc1-release-gate.yml` as a Darwin arm64-only draft/prerelease gate. Repository credentials may exist while downloading or publishing, but must be removed before candidate execution.
- [ ] Keep `VERSION=0.1-preview.1` during readiness, preserve the existing preview gate, and require `scripts/validate-public-tree.sh` to validate both historical preview and RC readiness contracts.
- [ ] Run public validation, shell syntax checks, and a deliberately corrupted export rejection test; commit, push, and require public CI success.

### Task 2: Prepare the public deep-trial experience

- [ ] Add `experiments/rc1/README.md` with a 15-minute path and exact commands for version/help, source check, project check, capability exercise, multi-module build/run, bounded server evidence, and comparison capture.
- [ ] Add public, non-implementation inputs under `experiments/rc1/hello`, `agent-review`, `capabilities`, `multi-module`, `server-bounded`, and `comparison`.
- [ ] Pin every fixture and expected machine-output digest to the sealed export. Do not invent output or mark an experiment measured before native execution.
- [ ] Document SQLite and bounded HTTP prerequisites, non-production limits, how to report failures, and how another language or agent should emit the same comparison record.

### Task 3: Receive—not produce—the private sealed export

- [ ] Require the development handoff to provide: private commit identity, `1.0.0-rc.1` version binding, Darwin arm64 archive, archive and binary hashes, canonical export manifest, target matrix, license digest, and path-free node-free/capability/multi-module/server evidence.
- [ ] Run the public verifier before copying any JSON to `runtime/rc1`; keep executable archives outside Git.
- [ ] Reject the handoff if two independent private exports differ, any private path/source/governance marker is present, the native binary reports another version, or a pending target is presented as measured.

### Task 4: Publish the RC identity atomically

- [ ] Import only verified JSON evidence into `runtime/rc1`.
- [ ] Change `VERSION`, `runtime/checksums.txt`, and `runtime/build-metadata.json` together to `1.0.0-rc.1`; include hashes only for the measured Darwin arm64 asset.
- [ ] Update `bin/revia` to download the RC only on measured Darwin arm64 and fail with a precise pending-target message elsewhere. Update PowerShell to report pending rather than advertise a missing Windows asset.
- [ ] Update bilingual README, Quickstart, release notes, compatibility, development status, evidence, and release policy with deep-trial commands, known limits, license, measured target, pending targets, and Stable blockers.
- [ ] Verify public tree, sealed export, launcher syntax, clean local install from a local release URL, deep-trial hashes, and leak scans; commit and push, then require CI success.

### Task 5: Create, gate, and publish `v1.0.0-rc.1`

- [ ] Create an annotated tag at the verified public commit and a GitHub prerelease draft named `Revia 1.0.0-rc.1`.
- [ ] Upload only the verified Darwin arm64 archive, checksums, public export manifest, license, and notice.
- [ ] Dispatch the RC gate with the exact tag; publish only through the successful gate.
- [ ] Perform an unauthenticated public download, verify archive/binary hashes, and run version/help plus the measured deep-trial smokes.
- [ ] Confirm the release remains a prerelease and both historical preview tags/assets are unchanged.

### Task 6: Close and communicate the milestone

- [ ] Record exact public commit, tag, asset digest, gate run, measured target, pending targets, and Stable blockers.
- [ ] Provide the official native-VM procedure for each remaining target; emulation may be used only for diagnostic exploration, never as native performance or final platform evidence.
- [ ] Run fresh final validation and clean/aligned checks before reporting completion.
