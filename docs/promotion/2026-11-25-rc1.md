# Revia RC1 promotion — 2026-11-25

## Published slice

The 2026-11-19 field note described an mtime staleness predicate as a
proposal. This round it became code: pull request
[#47](https://github.com/regrevia/Revia/pull/47) merged as `0194070`,
closing [#46](https://github.com/regrevia/Revia/issues/46). The inline
`const stale = !existsSync(NATIVE_BINARY) || newestNativeSourceMtime(NATIVE_ROOT) > statSync(NATIVE_BINARY).mtimeMs`
is gone; both conformance binaries now ask one named module,
`test/native-binary-staleness.js`, and equality classifies the binary as
stale.

The measured states, from a copy with mtimes preserved (predicate only, no
cargo):

| state | result |
| --- | --- |
| source touched | `stale True` |
| binary mtime equal to newest source mtime | `stale False` under the old `>`, `stale True` now |
| bytes changed, mtime restored | old code reused the binary (`9ae9ead6…` → `8c88155d…`) |
| `Cargo.lock` 65 s newer than the binary | `stale False` (extension filter) |

The `Cargo.lock` gap is unreachable in this tree: `native/Cargo.lock` covers
four workspace members and zero third-party dependencies. It is reachable
only with third-party dependencies.

The predicate answers one question — whether anything visible is newer than
the binary. The state that still reuses a rebuilt-away binary on purpose is
the one where someone preserves the mtime (`cp -p`, `tar x`, `rsync -t`, a
container layer). Byte-level provenance needs a persisted hash manifest,
which is a new durable state on a tree that has no third-party dependencies
and builds offline.

## Boundary

RC / evaluation-only / source-closed / `darwin-arm64` measured-native. Linux
x64, Windows x64, and Linux arm64 are pending. This does not claim Stable
V1.0, production safety, cross-platform equivalence, full byte determinism,
full A2A/MCP support, or Agent-native efficiency. The predicate is a guard,
not a bug report.
